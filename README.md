# Tomo-seq analysis for major research project (Hubrecht-2024)
This repository contains most of the code used in my Major Research Project (Hubrecht Institute, van Rooij group) as part of my master studies in Utrecht University (Bioinformatics and Biocomplexity MSc). The sequencing data was used to measure differential gene expression in heart tissue, in response to myocardial infarction, between the mammalian species *Mus musculus* and *Acomys cahirinus*. In the project the Tomo-seq data was combined with bulk RNA-seq from cell-cultures of fibroblasts and cardiomyocytes. Of particular interest were genes whose protein products are likely secreted by fibroblasts and which could interact with cardiomyocytes, possibly in ways that are relevant to the apparent tolerance to MI injury in *Acomys*. 

The Jupyter notebooks contain the code for the quality control, demultiplexing, mapping and quantification of the Tomo-seq data. These notebooks rely on functions and programs in the `./utils` and `./tools` directories. The inter-species RNA-seq task requires us to know one-to-one orthologs, which were determined using OrthoFinder (`./Orthofinder`). After mapping, the counts are processed with code contained in `./Count_data_processing`. Normalization is done for visualization purposes, and the un-normalized counts are used in DESeq2 (`./Differential_expression_analysis`).  
## 1. From reads to counts
### Quality control and demultiplexing
1. Quality control of the raw reads with [fastp](https://github.com/OpenGene/fastp)
2. Barcode error-correction within Hamming distance = 1.
3. Demultiplexing the reads between 96 barcodes. The demultiplexing follows a two-step process: the error-corrected R1 files are first demultiplexed using the barcodes provided in the text file, and the R2 files are then demultiplexed based on the header line IDs in the demultiplexed R1 files. 
### Read Mapping and quantification
The workflow has the option to choose from two read mapping methods: Salmon and STAR-RSEM. The motivation to use RSEM after STAR stems from the high number of multi-mapping reads detected for *Acomys cahirinus*. STAR natively outputs counts only for uniquely-mapping reads, where the *uniqueness* refers purely to genomic location, and not to any annotated feature. Therefore, a read can be labeled multi-mapping even if it maps to multiple locations within the same gene. A custom script was written to determine the gene-wise multimapping distribution for each read from STAR's transcriptome mapping output, which then was used used to filter out all reads that mapped to more than 2 genes before running RSEM. 
- [Salmon](https://salmon.readthedocs.io/en/latest/): the reads are mapped to reference transcriptome, and transcript counts are summarized to gene-level counts with [tximport](https://bioconductor.org/packages/release/bioc/html/tximport.html).
- [STAR](https://github.com/alexdobin/STAR): the reads are mapped to reference genome with `--quantMode TranscriptomeSAM` and the gene-level quantification is done with [RSEM](https://github.com/deweylab/RSEM). 
## 2. Orthologous gene inference
Doing RNA-seq analysis between two different species means that we will compare the transcriptional expression between orthologs - genes that have originated from a common ancestor. It is easiest to compare single-copy orthologs (that have not undergone duplication after phylogenetic split), as neo-functionalization and hypo-functionalization make the comparison of multi-copy orthologs more complex. The only way to distinguish between single-copy and multi-copy orthologs is through phylogenetic reconstruction methods, and it cannot be done with sequence similarity alone (e. g. reciprocal BLAST). This project used [OrthoFinder](https://github.com/davidemms/OrthoFinder) with species that were carefully selected to provide a good coverage between the phylogenetic branches of the target species.

- At least 32 GB of RAM. The more the merrier. Multiple processor cores wouldn't hurt.

## Tomo-seq Data
- The [Tomo-seq](https://pubmed.ncbi.nlm.nih.gov/27443932/) method is essentially bulk RNA-seq of thin cryosections, and the library amplification is done with barcoded primers to retain spatial information. This data was from infarcted animal hearts to perform differential gene expression analysis between two species: *Mus musculus* and *Acomys cahirinus*. The animals were sacrificed at time points 14- and 42 days after MI (n=2), and the hearts were cryosectioned in the direction of atrium --> apex into 96 × 80 μm slices. 
- After total RNA extraction, the mRNA was amplified with polyT primers with slice-specific 8-
bp barcodes. The 96 × 8-bp barcodes were designed to have a minimum Hamming distance of 2 between any
pair.
- The libraries were sequenced with NextSeq500, by paired-end sequencing which produced a pair of sequences per each
amplified fragment: a 26 bp (read 1) and 62 bp (read 2). Read 1 contained only the barcode
sequence and read 2 contained the sequence used for alignment, so practically from the
alignment standpoint these were single-end reads and Read 1 is only used for demultiplexing.
### Practical comments on the data
- the poly-T read amplification produced 3' end sequence fragments with an average length of ~50 bp, which means there is no gene length bias in the data and normalization methods like RPKM must not be used. There is, however, bias in the read start position on the fragments, so Salmon and RSEM must be run with settings that infer read start bias from the data. Reads map to forward strand (SF).
- The minimum Hamming distance between any two barcodes is 2 (to be more precise, there are 28 barcodes that have a minimum HD of 3 to any other of the 96 barcodes, the rest have minimum HD=2). This is relevant to barcode error correction, where we can correct sequencing errors by looking for permutations of the original sequences. For an 8-base DNA sequence, the set size of permutations within HD=1 is 33. For two 8-base DNA sequences that are HD=2 apart, there will be 2 permutations that are identical between the sets. Thus, the barcode error correction has to account for collisions by excluding permutations that are not unique to the barcode. Among the 96 barcodes, there are 16 barcodes that have an unique permutation set size of 27 (the lowest), because they have HD=2 with 3 other barcodes: 33-(3*2)=27. The `unambig_bcode_permuts.py` program accounts for these collisions. From practical standpoint, the bias from the uneven set sizes is minimal, as most (>90%) of the barcodes do not need error correction after QC anyway.
  - 28 barcodes have the full set of 33
  - 24 barcodes have 31 unambiguous sequences
  - 28 barcodes have 29 unambiguous sequences
  - 16 barcodes have 27 unambiguous sequences
- An important consideration for count normalization is that the RNA-seq data was not generated with methods that would allow for the inference of the base count distribution in samples independently (like how UMIs or the use of spike-in RNA would). This means the sample counts can only be normalized relative to one another, and not to any base state that actually existed. We are going to inevitably rely on some central tendency, therefore operating under the assumption that most genes are not differentially expressed. This most likely is not true between the samples from *Acomys cahirinus* and *Mus musculus*. The resulting bias was combated in this work by recognizing that the morphological zones of the infarcted heart (fibrotic infarct zone and remote zone) were similar between the species, in terms of gene expression of the ~18,000 one-to-one orthologs discovered with OrthoFinder. This is demonstrated by hierarchical clustering in the `Count_data_processing/Visualization` directory. Accordingly, the DESeq2's Median of Ratios normalization was done for samples belonging to either: same species and different zones, different species and the same zone, but not different species and different zones. TPM, RPKM and other methods that use division by total read count were avoided, as they have been shown to fail to account for what is known as the library composition bias - the disproportionate contribution of differentially expressed genes to the total count. Division by total read count can create false signals for genes that are not differentially expressed.
